# MPPI Offboard Control

`mppi_offboard_node` executes timestamped local horizons generated by
`production_mppi_node`.

## Takeoff

Before navigation, offboard sends a position setpoint at the configured initial
altitude. Takeoff completion is latched after altitude capture and the
configured hover interval.

## Horizon Execution

Each accepted horizon is validated for:

- increasing sequence;
- `map` frame;
- at least two finite points;
- a valid time window;
- every point and hold target inside `1.0 <= z < 32.0 m`;
- a finite stationary-hold target when requested.

At 50 Hz, offboard selects the horizon time at:

```text
now - valid_from + control_lookahead
```

It interpolates velocity, acceleration, vertical motion, yaw, and yaw rate
between neighboring samples and publishes a PX4 trajectory setpoint.

## Applied-Control Feedback

The acceleration and yaw-rate command actually selected by offboard is
published back to MPPI. The next MPPI update uses it to limit the first control
and avoid command discontinuities.

## Expired Or Missing Horizons

If no fresh horizon exists:

- moving vehicle: dynamically decelerate;
- nearly stopped vehicle: hold current position.

The old horizon is not extended beyond its validity deadline.

## Constrained Route Execution

Static `RouteSample3D` references carry altitude and speed constraints along
canonical air-passage spans. MPPI follows the same typed route continuously;
there is no separate passage hold or nearest-opening selector.

## Vehicle Destruction

A typed `VehicleDestroyed` event stops setpoint execution and latches bounded
PX4 force-disarm retries until the vehicle status confirms disarmed. The only
accepted causes are Gazebo `physical_collision`, mission-referee
`proximity_intercept`, and interceptor `proximity_collision`; vehicle ID, role,
and mission epoch must match the offboard instance.
Mission failure, goal arrival, stale state, and planner collision diagnostics do
not publish destruction and cannot request force-disarm.

## Removed Legacy Control

The current offboard node does not implement:

- long-path projection tracking;
- P/D cross-track control;
- curvature feedforward;
- path continuity stitching;
- path-id ACKs;
- velocity terminal capture;
- pending successor or after-hold activation.
